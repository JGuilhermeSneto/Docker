Docker, Contêineres & Computação em Nuvem

Relatório conceitual sobre arquitetura de contêineres, ciclo de vida de imagens, isolamento no nível do kernel Linux e comparação arquitetural com Máquinas Virtuais (VMs).

01

O que são Contêineres?

Um contêiner é uma unidade padronizada de software que empacota o código de uma aplicação e todas as suas dependências (binários, bibliotecas, arquivos de configuração e tempo de execução), garantindo que ela seja executada de maneira rápida, confiável e idêntica em qualquer ambiente de computação.

Mecanismo Linux Namespaces

Responsável pelo isolamento de visão: faz o processo dentro do contêiner acreditar que possui sua própria tabela de processos (PID), interfaces de rede (NET), pontos de montagem de arquivos (MNT), hostname (UTS) e comunicação inter-processos (IPC).

Control Groups (cgroups)

Responsável pela medição e limitação de recursos de hardware: controla quanta memória RAM, núcleos de CPU, I/O de disco e largura de banda de rede cada contêiner pode consumir, impedindo que um processo monopolize o servidor.

02

Imagens Docker & Camadas (Layers)

Uma Imagem Docker é um modelo somente-leitura (read-only snapshot) composto por várias camadas sobrepostas que utilizam sistemas de arquivos unificados (como OverlayFS). Quando um contêiner é iniciado, o Docker adiciona uma camada final fina de leitura e escrita (Container Layer).

03

O que é o Dockerfile e suas Diretivas

O Dockerfile é uma receita declarativa em texto contendo as instruções sequenciais que o Docker utiliza para construir automaticamente a imagem do contêiner.

FROM Define a imagem base de partida (ex: python:3.11-slim).
WORKDIR Define o diretório de trabalho padrão dentro do contêiner para os próximos comandos.
COPY Copia arquivos da máquina do desenvolvedor (contexto de build) para o contêiner.
RUN Executa comandos durante o build para gerar novas camadas (ex: instalação de pacotes).
EXPOSE Documenta a porta de rede que a aplicação interna do contêiner escuta (ex: 8000).
CMD / ENTRYPOINT Instrução executada no momento em que o contêiner é iniciado para rodar o processo principal.

🛡️ Isolamento

Cada contêiner opera em um ambiente confinado. Falhas ou crashes dentro de um contêiner não afetam o sistema hospedeiro ou outros contêineres vizinhos. O contêiner possui seu próprio sistema de arquivos em raiz virtual (chroot), rede privativa com IP próprio e tabela de processos isolada.

🌐 Portabilidade na Nuvem

Resolve o clássico dilema: "Na minha máquina funciona, mas em produção não". Como o contêiner empacota o sistema operacional base, a versão exata do Python, as bibliotecas e as configurações, ele executa com comportamento 100% idêntico no Windows, Linux, macOS, AWS, Azure ou Google Cloud.

05

Comparativo: Contêineres vs Máquinas Virtuais (VMs)

Enquanto as Máquinas Virtuais virtualizam o hardware físico (necessitando de um sistema operacional convidado completo e um Hypervisor), os contêineres virtualizam apenas o sistema operacional, compartilhando diretamente o mesmo Kernel da máquina hospedeira.

Critério 🐳 Contêineres Docker 🖥️ Máquinas Virtuais (VMs)
Abstração / Nível Nível de Sistema Operacional (Kernel Compartilhado) Nível de Hardware (Hypervisor: KVM, ESXi, VirtualBox)
Sistema Operacional Não requer SO Convidado (Guest OS) Requer SO Completo em cada VM (GBs de disco)
Tempo de Inicialização Milissegundos a poucos segundos Minutos (boot completo do sistema operacional)
Tamanho da Imagem Muito leve: de dezenas a centenas de MBs Pesado: vários Gigabytes (10 GB a 50 GB+)
Consumo de Recursos (Overhead) Mínimo / Quase nulo (processos nativos) Alto (duplicação de kernels, drivers e memória)
Densidade de Execução Centenas de contêineres no mesmo servidor Poucas dezenas de VMs por servidor físico
Nível de Isolamento Isolamento lógico no nível de processos Isolamento forte no nível de hardware
